# Plan: Загрузка файлов во встречах

**PRD:** @docs/prd-загрузка-файла-встречи-для-последующего-хранения-и-обработки-а-также-интерфейса-загрузки-и-отображения-внутри-встречи.md
**Дата:** 2026-09-29

## Контекст (из анализа кода)

- Экрана/страницы встречи на frontend сейчас нет — есть только главная, `login`, `register`.
- Механизма чата (WebSocket/Socket.io) нет ни на backend, ни на frontend. В плане ниже «чат встречи» реализуется как список файлов на экране встречи с ручным/периодическим обновлением, без realtime-канала — PRD не требует push-обновлений, только видимость файла всем участникам.
- `MeetingsService` хранит встречи in-memory (`{ id, title, date, participants, createdBy, createdAt }`), проверка «создатель» сделана фильтром `createdBy === userId`, отдельного guard/decorator нет.
- Multer, sharp, ffmpeg, генераторы превью PDF/презентаций — не установлены. Раздачи статики и лимитов body-parser под большие файлы — нет.

## Фазы реализации

### Фаза 1: Backend — загрузка, хранение и скачивание файлов
**Цель:** Сквозной рабочий путь через API: создатель встречи загружает файл, файл хранится на диске, участники видят список и могут скачать файл. Превью пока не генерируется.
**Затрагивает:** backend

**Задачи:**
- [ ] Сущность `MeetingFile` + `FilesService` (in-memory метаданные, привязка к `meetingId`), сохранение содержимого на локальный диск с уникальным именем/путём.
- [ ] `POST /meetings/:id/files` — загрузка файла (только `createdBy` встречи), проверка типа (документы/изображения/видео/презентации/PDF) и лимита 2 ГБ.
- [ ] `GET /meetings/:id/files` — список файлов встречи (доступен всем участникам), поля: имя, размер, тип, дата загрузки, ссылка на превью (пока `null`).
- [ ] `GET /meetings/:id/files/:fileId/download` — скачивание файла с проверкой, что запрашивающий — участник встречи (401/403/404 для остальных).
- [ ] Настройка лимитов Express/Nest (body size, multer) под файлы до 2 ГБ и понятные ошибки при превышении лимита и недопустимом типе.

**Когда готово:** через API создатель встречи загружает файл любого разрешённого типа, получает его в списке, любой участник встречи скачивает файл и он идентичен исходному (совпадает хеш). Файл 2049 МБ отклоняется, файл ровно 2 ГБ загружается. Не-создатель получает 403 на загрузку. Неавторизованный запрос на скачивание получает 401/403/404.

### Фаза 2: Frontend — экран встречи, загрузка и список файлов
**Цель:** Дать пользователю интерфейс для сценариев из Фазы 1: экран встречи, форма загрузки с прогрессом, список файлов со скачиванием.
**Затрагивает:** frontend

**Задачи:**
- [ ] Страница экрана встречи (например `/meetings/[id]`) с названием, датой, участниками.
- [ ] Форма загрузки файла для создателя встречи с отображением прогресса и результата (успех/ошибка); скрыта или недоступна для остальных участников.
- [ ] Список файлов встречи на экране (имя, иконка типа, размер, дата, кнопка «Скачать»).
- [ ] Обновление списка после успешной загрузки и периодический рефетч, чтобы новые файлы появлялись у остальных участников без перезагрузки страницы.
- [ ] Обработка ошибок загрузки (превышение лимита, недопустимый тип, отказ 403) с понятным сообщением пользователю.

**Когда готово:** создатель встречи открывает экран встречи, выбирает файл, видит прогресс загрузки и результат; файл появляется в списке. Участник (не создатель) видит тот же список и может скачать файл, но не видит форму загрузки.

### Фаза 3: Backend — генерация превью
**Цель:** После загрузки для изображений/видео/PDF/презентаций в фоне генерируется превью и становится доступным по ссылке из списка файлов.
**Затрагивает:** backend

**Задачи:**
- [ ] Генерация миниатюры для изображений (sharp), сохранение как отдельный файл превью.
- [ ] Извлечение первого кадра для видео (ffmpeg), сохранение как изображение-превью.
- [ ] Рендер первой страницы PDF в изображение-превью.
- [ ] Рендер первого слайда презентаций в изображение-превью.
- [ ] Фоновый запуск генерации после ответа на загрузку (не блокирует запрос) + `GET /meetings/:id/files/:fileId/preview`, отдающий изображение превью, когда оно готово; для документов превью не генерируется (только имя/тип, как и раньше).

**Когда готово:** после загрузки изображения/видео/PDF/презентации в списке файлов появляется рабочая ссылка на превью соответствующего типа (может появиться с задержкой из-за фоновой обработки). Для документов превью не появляется, попытка запроса `preview` для документа возвращает 404 или пустой ответ, зафиксированный контрактом.

### Фаза 4: Frontend — отображение превью файлов
**Цель:** Показать сгенерированные превью в списке файлов встречи для всех участников, с fallback-иконкой для документов и файлов, чьё превью ещё не готово.
**Затрагивает:** frontend

**Задачи:**
- [ ] Карточка файла показывает превью-изображение (миниатюра/кадр/страница), полученное из `preview`-ссылки.
- [ ] Плейсхолдер-иконка для документов и для файлов, чьё превью ещё не сгенерировано, с повторным опросом до появления превью.
- [ ] Проверка вручную под двумя разными пользователями (создатель и участник), что превью видно обоим, а не только загрузившему.

**Когда готово:** для всех типов файлов из скоупа (кроме документов) в списке появляется корректное превью у всех участников встречи; для документов стабильно отображаются имя и иконка типа.
